Focuser · Painel de testes da API (V1)

Cada ação faz uma requisição real à API. Nada aqui é simulado: status e respostas exibidos são os retornados pelo servidor.

Configuração da API

Abra o painel por http://localhost:8080 (npm run panel) e use localhost na URL-base (não misture com 127.0.0.1: o cookie de sessão é SameSite=Lax). A origem do painel precisa estar em CORS_ORIGINS da API. Abrir via file:// não funciona (CORS/cookies).

Fluxo principal automático

Cadastro → login → /me → criar hábito → check-in → duplicata → dashboard → progresso → logout → /me sem sessão. Cria um usuário painel_*@focuser.test e substitui a sessão atual do navegador. Use apenas em ambiente de desenvolvimento/teste.

Como a autenticação funciona

Sessão por cookie httpOnly (o painel nunca vê o token). Requisições de escrita enviam X-Focuser-Client: web (defesa CSRF) e usam credentials: include. Senhas não são salvas no navegador; somente a URL-base é guardada em localStorage.

Não implementados na V1 (sem ação no painel): alteração/recuperação de senha, exclusão de conta, verificação de e-mail.

Isolamento entre usuários (A × B)

1) Logado como A: crie um hábito (e um check-in) e clique em “Fixar IDs”. 2) Faça logout e entre como B (outro cadastro). 3) Clique em “Executar tentativas”: todas devem ser rejeitadas (404/400) e a lista de B não pode conter o hábito de A. 4) Volte como A e confira que o hábito segue intacto. Use só dados de teste: se o isolamento falhar, estas tentativas podem alterar ou apagar dados reais de A.

Registrar conclusão (hábito do contexto)

Clique em “Registrar” duas vezes para testar a duplicata (espera 409). Retroativo até 7 dias; futuro, antes do início do hábito e dias não programados são rejeitados (422).
